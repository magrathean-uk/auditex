## System overview
`src/azure_tenant_audit/` is the Microsoft 365 engine: collectors and adapters read the tenant through the guarded Graph and PowerShell paths, `normalize` and `findings` build evidence, `value_rules/` answers the 102 SCuBA policies, `explainer/` renders the deterministic template, `output_redaction` applies the redaction profiles and D5 masking, and `finalize` seals a validated run bundle. It never imports `auditex`.
`src/auditex/` is the product layer: the `auditex` CLI (including `assess`) and guided flows, reporting, exporters, compare and drift, customer packs, the Google Workspace provider and the local MCP server; it calls the engine and reads bundles. There is no model layer in the product (removed in 1.4.0, v3 DEC-005).
Configs, schemas and profiles under `configs/`, `schemas/` and `profiles/` drive collection scope and contracts; shipped content is listed in both `pyproject.toml` data-files and `shipped_content.py`. Gates are local only (no hosted CI): `make lint`, `make test`, `make contract-smoke`, `make acceptance`, `make release-check`, `make audit-deps`, `make dist` with the release smoke and `scripts/check-reproducible-build.py`.
Track B lives outside this repository: the AIRR kit folder of the development kit holds the standalone trainer, data, judging code and run records for Isambard-AI; it uses the released 1.4.0 wheel, and `src/` never imports it. Its only repository output is `.plan/work/<id>/result.md`. `tenant-bootstrap/` is lab tooling whose `azure_tenant_audit/` package forwards to `src/`.

## Conventions
Python 3.11+, `.venv/bin/python`; pytest with `pythonpath = src`; tests in `tests/test_<area>_*.py`, fixtures under `tests/fixtures/`, auth and secret paths behind `tests/conftest.py`; Ruff pinned to the pre-commit hook version through `make lint`, rule set E4, E7, E9, F and from M00-T01 also W, I, B, UP.
CLI parsers use `allow_abbrev=False`; every secret-carrying flag sits in its redaction set with an abbreviation and a redaction test. Feature flags are environment variables read in `src/auditex/features.py` (`AUDITEX_ENABLE_RESPONSE` lab only).
Shipped content changes update `pyproject.toml` data-files and `shipped_content.py` together; rule changes rerun `scripts/generate-rule-packs.py`. Removals go through the deletion gate: G approves the exact path list first; the orchestrator writes one `.plan/CLEANUP.md` row per approved path (`| \`path\` | reason | evidence | DEC-nnn | |`, no `|` inside cells) and fills the commit column after the merge.
Commits signed, gitleaks-clean, one coherent change each, staged by pathspec; no workstation paths, credentials, live evidence, held-out or sealed rows in the public repo.

### Plan v4 evidence rules
- Under `.plan/work/` only `result.md` files and `PLAN-*/*.md` are tracked; design notes and logs exist only in the main checkout. Durable facts a predicate reads live in tracked files: `.plan/DECISIONS.md`, `.plan/CLEANUP.md`, `.plan/work/ledger.tsv`, `result.md` files or repository files.
- Plan v2 and v3 used the same task ids; their work folders are archived under `.plan/archive/plan-v2/work/` and `.plan/archive/plan-v3/work/`. Predicates bind to plan v4 merges (after tag `v1.4.0`) and plan v4 DEC entries; older decisions are cited as "v2 DEC-nnn" and "v3 DEC-nnn". Local milestone tags are `v4-Mxx`, because `M00` to `M03` already exist.
- Track B result lines: each fact a DoD item greps sits on its own line under `### Findings` (for example `reproduction: pass`, `gpu-hours: repro 58`), never as an extra RESULT key. `gpu-hours: <stage> <used>` is the task's cumulative use, every attempt, failed and retried jobs included, from the scheduler accounting; the cap is never written by the author.
- Budget binding, for the stages `S` of a milestone: the cap and the DEC that set it come from that stage's row of the master-plan budget table; the DEC must have approver G and status approved; the task list comes from the same row; the cap must be a whole number and the sum of the tasks' `gpu-hours: S` lines must not exceed it, summed and compared in exact decimal arithmetic by `bc` with no intermediate rounding (probed: 2048.001 against a 2048 cap fails, 2047.9 plus 0.1 passes; a missing, negative or malformed line, a non-integer cap or an unapproved DEC fails). Moving hours or releasing the reserve changes a row's cap and its set-by DEC only after G approves that DEC:
  ``for s in S; do row=$(grep "^| $s | " .plan/master-plan.md) && c=$(printf '%s\n' "$row" | awk -F'|' '{gsub(/[ ,]/,"",$4); print $4}') && printf '%s\n' "$c" | grep -qE '^[0-9]+$' && d=$(printf '%s\n' "$row" | awk -F'|' '{gsub(/ /,"",$5); print $5}') && grep -A8 "^## $d " .plan/DECISIONS.md | grep -q '^- approver: G' && grep -A8 "^## $d " .plan/DECISIONS.md | grep -q '^- status: approved' && e=0 && for t in $(printf '%s\n' "$row" | awk -F'|' '{gsub(/,/," ",$3); print $3}'); do v=$(sed -n "s/^gpu-hours: $s \([0-9][0-9]*\(\.[0-9][0-9]*\)\{0,1\}\)\$/\1/p" ".plan/work/$t/result.md" | head -1) && test -n "$v" && e="$e+$v" || exit 1; done && test "$(printf 'r=0\nif (%s <= %s) r=1\nr\n' "$e" "$c" | bc)" = 1 || exit 1; done``
