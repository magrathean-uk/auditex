## System overview
`src/azure_tenant_audit/` is the Microsoft 365 engine: collectors and adapters read the tenant through the guarded Graph and PowerShell paths, `normalize` and `findings` build evidence, `value_rules/` answers the 102 SCuBA policies, `explainer/` renders the deterministic template, and `finalize` seals a validated run bundle. It never imports `auditex`.
`src/auditex/` is the product layer: the `auditex` CLI and guided flows, reporting, exporters, compare and drift, customer packs, the Google Workspace provider and the local MCP server; it calls the engine and reads bundles.
Configs, schemas and profiles under `configs/`, `schemas/` and `profiles/` drive collection scope and contracts; shipped content is listed in both `pyproject.toml` data-files and `shipped_content.py`.
Gates are local only: `make lint`, `make test`, `make contract-smoke`, `make release-check` (archive and wheel check, rule-pack drift, taint scan, gitleaks), `make audit-deps` (base and every extra), `make dist` with the wheel and sdist release smoke and `scripts/check-reproducible-build.py`.
The parked model layer and `tenant-bootstrap/` (lab tooling with writable operations) ship but are frozen for 1.3.0: their call sites are classified and the `model_train` extra is audited, nothing more.

Test files: a module owns the test globs in its row. Any other `tests/test_*.py` belongs to the module whose code it imports first (engine before product), and the task that changes it names it on its `files:` line. Two tasks never share a file at the same time, whatever the module.

## Interfaces
- Engine to product: `azure_tenant_audit` public functions and the run-bundle layout in `docs/reference/output-contract.md`; `CONTRACT_VERSION` in `src/azure_tenant_audit/contracts.py` changes only with a DECISIONS.md entry and an output-contract date change.
- Value rules to everything else: `configs/scuba-value-rules.json` (spec v3.9.1) and the rule registry in `value_rules/__init__.py`; the explainer reads catalogue cells only, never evidence outside the cited, redacted sections, and never changes a verdict.
- Redaction: `secret_hygiene.redact_argv` with each parser's sensitive-flag set (`command_runner.SENSITIVE_ARGS`, the Google `run._SENSITIVE_COMMAND_FLAGS`, the engine `secret_hygiene.SENSITIVE_ARG_FLAGS` and `auth_runtime.SENSITIVE_CLI_ARGS`); D3 profiles via `output_redaction`. A new secret-carrying flag lands in its set and its tests in the same commit.
- Transport policy (frozen here; M01-T02 maps every call site to one class, M01-T03 and M01-T04 enforce it). Every outbound call is one of: (1) tenant read: GET through `graph._request` and the read guard, or a GET to the Power BI, Power Platform or Teams admin REST APIs; (2) token: Entra and Google OAuth token endpoint POSTs; (3) Graph `$batch` POST whose sub-requests are all GET; (4) public lookup: DNS-over-HTTPS and exposure GETs; (5) operator-configured outbound sink: `notify.py` Teams and Slack webhooks, Jira and GitHub issue POSTs, sent only when the operator sets the sink variables, redacted, never to the tenant; (6) parked model endpoint: `model_serving.py` chat-completions POST, loopback by default, off unless the operator configures it; (7) lab-only response path behind `AUDITEX_ENABLE_RESPONSE`; (8) local subprocess: sign-in CLIs, PowerShell with read-allow-listed cmdlets only, the probe and local system tools. A site outside these classes needs sol and, for a product question, G before it lands.
- Read boundaries: no collector requests message, mail, file or attachment content (`api_inventory` content rules); PowerShell cmdlets come only from the `api_inventory` read allow-list; Google calls are read methods under read-only or metadata-only scopes.
- MCP: tool names, arguments and `read_only_hint` in `mcp_registry.py`; path arguments confined by `mcp_paths.py` to `AUDITEX_MCP_ROOT`.

## Conventions
Python 3.11+, `.venv/bin/python`; pytest with `pythonpath = src`; tests in `tests/test_<area>_*.py`, fixtures under `tests/fixtures/`, auth and secret paths behind `tests/conftest.py`.
CLI parsers use `allow_abbrev=False`; every secret-carrying flag sits in its redaction set with an abbreviation and a redaction test.
Feature flags are environment variables read in `src/auditex/features.py` (`AUDITEX_ENABLE_RESPONSE` lab only; hidden `AUDITEX_DISABLE_VALUE_RULES` accepted and ignored).
Shipped content changes update `pyproject.toml` data-files and `shipped_content.py` together; rule changes rerun `scripts/generate-rule-packs.py`.
Commits signed, gitleaks-clean, one coherent change each, staged by pathspec; no workstation paths, credentials or live evidence in the public repo.
